## New finding: fresh install dies on ≤4GB-memory hosts (DF-WARPFS-142)

README no-sudo path on a fresh bunker-mvp agent: clone 2s rc=0, rustup minimal 11s
rc=0, 460 crates compiled over ~100 min (host loadavg 64 — numbers polluted), then
libduckdb-sys C++ died mid-build: `cc-rs: signal 6 (SIGABRT) (core dumped)` on
ub_src_transaction.cpp, no binary, no smoke. Agent memory cap is 4.0 GB (metrics showed
3.8/4.0 GB in use during the build); cc-rs reports the OOM as a bare SIGABRT with no
memory hint. All prior install PASSes ran on bigger hosts. Filed DF-WARPFS-142 (P1).
The install premise ("no-sudo path works on any bare image") is therefore UNPROVEN on
memory-capped hosts — README carries no memory requirement.
