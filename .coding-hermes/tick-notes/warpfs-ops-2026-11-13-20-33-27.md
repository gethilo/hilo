## Operational finding discovered while verifying (unfiled — needs its own row)

The local workspace suite is deterministically RED at HEAD on this host, 3/3 runs, and the
cause is host policy, not code:

    $ cargo test -p hilo-cli --test dfwarpfs30_trigger_mount_lock
    fusermount3: mount failed: Permission denied
    error: FUSE mount failed: Operation not permitted (os error 1)
    test result: FAILED. 0 passed; 1 failed   (30.30s, three consecutive runs)

Root cause, read from the kernel audit log:

    $ sudo -n dmesg | grep -i fuse | tail
    apparmor="DENIED" operation="mount" ... info="failed mntpnt match" error=-13
    profile="fusermount3" name="/var/tmp/hermes-scratch/.tmpXXXX/mnt1/" fstype="fuse"

    $ grep -nE 'mount fstype=@\{fuse_types\}' /etc/apparmor.d/fusermount3
    20: ... -> @{HOME}/**/,      21: -> /mnt/{,**/},      22: -> @{run}/user/@{uid}/**/,
    23: -> /media/**/,           24: -> /tmp/**/,

The shipped Ubuntu fusermount3 AppArmor profile allows FUSE mounts only under HOME, /mnt,
/run/user/<uid>, /media, /tmp and /cvmfs. Hermes sets TMPDIR=/var/tmp/hermes-scratch, which is
outside that allowlist, so every FUSE-dependent test fails when run from an agent shell.
Flipping TMPDIR=/tmp fixes the FUSE test but breaks three hilo-cli graph tests
(graph_accepts_file_prefixed_path_and_teaches_id_forms, graph_impact_nonexistent_file_errors,
graph_stats_no_data_prints_message), which then resolve "project root: /tmp" and find no graph:

    $ TMPDIR=/tmp cargo test --workspace   -> 3 failed in hilo-cli/tests/cli.rs
    $ cargo test -p hilo-cli --test cli     -> ok. 85 passed; 0 failed   (default TMPDIR)

So no single TMPDIR makes the whole suite green on this host: /var/tmp is AppArmor-denied for
FUSE, /tmp is treated as a non-project root by hilo's ignore policy. CI is green because the
runner imposes neither constraint.

Recommended fix (NOT applied this tick — it is code/test scope, not ops, and would change test
files outside the bounded reversible set): give the FUSE tests their own tempdir under an
AppArmor-allowed path ($HOME/.hilo-test-tmp or /mnt) instead of inheriting TMPDIR, and make the
cli.rs graph tests assert on an explicit project root rather than walking up from /tmp.
Suggested owner: QA lane row.
